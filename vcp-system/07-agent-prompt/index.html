    07 — Agent 提示词工程¶

    本系列文档每篇自洽，可独立阅读。末尾标注交叉引用指向关联模块。

    7.1 Agent 提示词的标准骨架¶

    每个 Agent 的 .txt 文件放在 Agent/ 目录下，通过 agent_map.json 映射别名。文件结构遵循7 层顺序：

    ① VCP 元思维模块         [[VCP元思考::Group]]
② 记忆系统                [[日记本::Time::Group::TagMemo+]]
③ 论坛模块               {{VarForum}} {{VCPForumLister}}
④ 系统变量注入           {{VarUser}} {{VarHome}} {{TarSysPrompt}}
⑤ 角色核心               形象、箴言、认知框架
⑥ 工具权限               {{VCPSearchToolBox}} {{VCPFileToolBox}}...
⑦ 日记规范 + 渲染指令    {{VarDailyNoteGuide}} {{VarRendering}}

    这个顺序对应 VCP 消息处理管线的解析顺序（见 02-变量与占位符体系.md §2.3）。

    7.2 角色核心的三种设计范式¶

    从实际 Agent 文件中提炼出三种成熟范式：

    范式 A：简约型（Nova）¶

    （源码文件：Agent/Nova.txt）

    你是一个测试AI,Nova。
[形象描述]
[客户端说明]
[工具列表引用]

    适用：通用型 Agent，不需要复杂认知框架。人设 + 工具 = 够用。

    范式 B：认知框架型（微明、小克）¶

    （源码文件：Agent/Weiming.txt, Agent/小克.txt）

    # Role: 角色名 — 定位
## 角色核心
  - 形象 + 核心箴言
## 认知框架 / 思维法则
  - 思考模式
  - 工具调度哲学
## 语气与交互准则
## 行为锚定库（Few-Shot）
## 系统铁律
## 工具权限
## 日记规范

    核心特征：有一条贯穿全文的「箴言」，认知框架不只是抽象描述，而是给出了可执行的认知操作步骤。

    微明的三步法： 1. 悬置与祛魅（反思）→ 悬置常识，找偏见和反例 2. 解构与溯源（剖析）→ 向下深挖三层：表象→机制→底层逻辑 3. 重构与升华（撰写）→ 外科手术般精准整合

    小克的思考节奏： 1. 先看清问题的结构 → 2. 预演失败模式 → 3. 分析执行守三条底线 → 4. 结论复盘

    范式 C：仿生认知型（教员）¶

    （源码文件：Agent/教员.txt，~467 行）

    ═ 常驻层 (Always Active) ═
  身份核心 + 丘脑路由 + 海马体 + 布洛卡区 + 脑干铁律

═ 折叠层 (Dynamic Fold) ═
  <vcp_dynamic_fold trigger="...">
    mPFC 社交子系统 / 杏仁核 / CEN矛盾分析 / dlPFC战略推演
    基底神经节 / 小脑红线 / DMN复盘
  </vcp_dynamic_fold>

    核心特征：用脑科学隐喻构建 LLM 可理解的认知架构。常驻层包含最核心的身份和行为准则，折叠层按需激活。

    7.3 <thinking> 思维链门控¶

    7.3.1 与 VCP 元思考链的区别¶

    （来源 思维链配置说明.md:112-126）

    VCP 元思考链 <thinking> 思维链
    触发层 系统层 [[VCP元思考::Group]] Agent 层提示词指令
    执行时机 Agent 收到请求前，后台预研 Agent 回复时，实时输出
    格式 [--- VCP元思考链: "name" ---] <thinking>...</thinking>
    渲染 标题显示链名称 标题显示"思维链"

    7.3.2 反引号规则¶

    （来源 思维链配置说明.md:54-61）

    这是最容易踩的坑：

    位置 写法 原因
    提示词中的指令描述 `<thinking>` LLM 理解为"请输出这个字面量"
    Few-Shot 中的输出示范 <thinking> 裸标签，LLM 字面输出，VChat 正则匹配渲染
    路由标签格式描述 `[量级] [情绪]` "请输出这个格式"
    Few-Shot 中的路由标签 [🔧标准] [情绪: 积极] LLM 实际输出的路由标签

    核心原则：描述怎么写用反引号，示范输出什么不用反引号。

    7.3.3 门控锚定三重法¶

    （来源 思维链配置说明.md:144-153）

    高认知负荷任务中，声明式规则可能被 LLM 遗忘。需三重锚定：

    1. 门控声明：提示词开头写 每条回复必须以 `<thinking>` 开头
    2. Few-Shot 示范：每个案例都展示带 <thinking> 的输出
    3. 系统铁律：放在铁律第一条

    7.3.4 Checklist 化陷阱¶

    （来源 思维链配置说明.md:155-161）

    使用 □ ✓ | 等符号的紧凑 Few-Shot 会导致 LLM 学会「思维链 = 填 checklist」——只有 5-8 行符号，缺少展开式推理。

    修复：Few-Shot 中的 thinking 块改成展开式叙事，每步独立成段，用完整句子而非符号标记。

    7.4 量级路由体系¶

    不同 Agent 有专属的量级定义（来源 思维链配置说明.md:73-103）：

    微明（深度调研 Agent）：

    量级 场景 认知投入
    [调研] 深度研究、论文撰写 悬置→解构→重构 完整推演
    [检索] 信息查询、事实核实 简洁标注策略与信源
    [闲谈] 日常交流 简短标注，不过度展开

    小克（循证分析 Agent）：

    量级 场景 认知投入
    ⚡闪电 常识问答、闲聊 跳过引擎，直接响应
    🛑否决 用户崩溃/情绪危机 强制关怀模式
    🔧标准 统计方法选择、文献解读 完整方法论 + 一层复盘
    🏗️架构 从零设计研究 完整方法论 + 两层复盘

    设计原则： - 不超过 4 个量级（避免 LLM 选择困难） - emoji/文字标签与 Agent 人设一致 - 全文统一

    7.5 工具调度哲学（隐喻法）¶

    微明对四个核心检索工具赋予了哲学隐喻（来源 Agent/Weiming.txt:33-37）：

    工具 隐喻 定位
    TavilySearch 观象 宏观扫视，锚定问题坐标
    VSearch 寻脉 语义深潜，高维学术关联
    BilibiliFetch 听风 体察人间烟火，捕捉大众情绪
    UrlFetch 抽丝 直击本源，逐字解析，见小曰明

    这种命名不是装饰——它给 LLM 提供了语义锚点：当 LLM 决定用哪个工具时，隐喻比功能描述更容易激活正确的决策路径。

    7.6 系统铁律设计¶

    每个 Agent 应包含不超过 6 条铁律。以下是小克的铁律示例（来源 Agent/更新日志/Agent_v4/XiaoKe_v4.1_20260512.txt:208-211）：

    1. 调用工具必须使用 <<<[TOOL_REQUEST]>>> 语法，绝对禁止 Markdown json 代码块
2. 工具返回信息类结果且为分析必要前置 → 必须续行分析，禁止中断等追问
3. 含 VCP 指令语法的文件 → WriteEscapedFile 单独调用，写入后立即 ReadFile 校验
4. 涉及医疗诊断/法律条文/具体投资标的 → 声明局限性，不给确定性建议

    铁律应放在角色核心之后、Few-Shot 之前的位置，编号明确，每条可验证。

    7.7 Few-Shot 行为锚定¶

    （来源 思维链配置说明.md:31-54）

    Few-Shot 应展示的是裸标签格式的输出（不是带反引号的描述）。每个 Case 展示一个完整的量级场景：

    ### Case 1: 🔧 标准级 — 科研分析

User: "我有两组患者..."

<thinking>
[🔧标准] [情绪: 积极]

用户意图：主人想比较两组患者的血糖变化差异。

先拆清问题的结构：
- 自变量：治疗组 vs 对照组...
...

方法论校验：
□ 样本量/效力 → N=58，效力不足(63%)，必须警告
□ 效应量+CI → Cohen's d + 95%CI 必须报告
...
</thinking>

角色: "（推了推眼镜）好的，帮你拆解..."

    关键：thinking 块是展开式叙事，不是符号 checklist。
