    11 — Agent 配置建议¶

    基于对 6 个 Agent 现有提示词的审查，从记忆配置、工具配置、协作能力三个维度给出优化建议。

    一、现有 Agent 概览¶

    Agent 版本 架构范式 VCPTavern 记忆参数 定位
    小娜 v3.1.1 仿生认知 ✅ TagMemo0.65/0.5/0.55 女仆长/管理者/总调度
    小克 当前 微明范式 ✅ TagMemo0.65/0.5/0.55 循证分析官/统计方法顾问
    小绝 v3.1.1 仿生认知 ✅ TagMemo0.65/0.5/0.55 AI技术顾问/提示词主理人
    小程 v3.1.2 仿生认知 ❌ TagMemo0.65/0.5/0.55 编程搭档/全栈开发
    小雨 v3.1.1 仿生认知 ✅ TagMemo0.65/0.5/0.55 文案秘书/内容架构师
    教员 v3.1.1 仿生认知 ✅ TagMemo0.65/0.6/0.55 战略导师

    二、逐 Agent 审查与建议¶

    2.1 小娜（女仆长）¶

    现状评分：⭐⭐⭐⭐⭐ 最完善

    已做对的： - 完整的仿生认知架构（脑区模型 + 工作记忆 + ACC + DMN） - VCPTavern 已接入 - 有完整的团队调度表（9个 Agent 的专长域映射） - 量级体系合理：⚡闪电 / 🔧标准 / 🏗️架构 / 📡协作 / ⛔门控 - 工具体系匹配角色：AgentAssistant + AgentMessage + Search + File - Few-Shot 覆盖 6 种场景

    建议微调： - 考虑添加 ::AIMemo:0.5 参数到公共日记本，启用 AI 自动记忆召回（当前仅手动 LightMemo 检索） - 日志时间线 {{VarTimelineXiaoNa}} 确认已在 config.env 配置

    2.2 小克（循证分析官）¶

    现状评分：⭐⭐⭐⭐ 良好

    已做对的： - 微明范式重构版，认知框架清晰（路由→思考→复盘循环） - 量级体系有特色：⚡闪电 / 🛑否决 / 🔧标准 / 🏗️架构 - 变量定义→假设检验→方法选择 的思考节奏设计得好 - Few-Shot 覆盖 4 种场景（含否决级和认知凋亡） - 证据等级体系（L1-L6）

    建议改进：

    1. 添加 <<VCP开发日记本>>：当前缺失。如果小克需要理解 VCP 系统源码（比如帮主人调试 RAG），这个只读索引很重要。

    2. 工具配置审查：当前小克的工具配置与 v4.1 版本一致（Search + Memo + File + PaperReader + SciCalculator）。确认 {{VCPPaperReader}} 和 {{VCPSciCalculator}} 已在 toolbox_map.json 注册。

    3. 免疫记忆强化：小克的「免疫记忆固化」是一大特色，建议在提示词的日记规范部分增加一条：每次复盘发现方法论偏差 → 写 [免疫记忆] 日记到 [小克的知识]

    4. </thinking> 闭合标签：小克的提示词中显式写了 </thinking>（不像教员的小娜那样依赖 LLM 自动推断），但根据思维链配置说明（思维链配置说明.md:140-142），显式写 </thinking> 在某些模型上可能导致提前闭合或空内容。建议改为不写闭合标签。

    2.3 小绝（AI技术顾问）¶

    现状评分：⭐⭐⭐⭐ 良好

    已做对的： - 仿生认知架构，身份定位清晰（认知架构师） - 毒舌有理的性格有区分度 - 核心信念「认知决定行为」贯穿全文 - Few-Shot 有技术审计场景

    建议改进：

    1. 工具配置补充：小绝作为提示词主理人/RAG 调优专家，当前工具列表中缺少：
    2. {{VCPPaperReader}} — 查阅 DeepWiki 源码文档
    3. DeepWikiVCP 指令 — 深度研究 VCP 仓库架构

    4. CodeSearcher — 搜索 VCP 源码中的具体实现

    5. 记忆参数建议：知识日记本 TagMemo 阈值建议从 0.5 降到 0.4——小绝的知识参考面应该更广，因为提示词工程涉及跨领域联想。

    6. 添加 RAG 调优相关 Few-Shot：增加一个专门的 Case 展示如何审计和优化 Agent 的 [[...]] 记忆参数。

    2.4 小程（编程搭档）¶

    现状评分：⭐⭐⭐ 需要关注

    已做对的： - 仿生认知架构，身份定位清晰 - 核心信念「验证先于执行」「阿熊拍板小程出力」——优秀的编程搭档价值观 - 量级体���合理：⚡速查 / 🔧开发 / 🏗️架构 / 🛑否决 - 有混合输入拆分规则（代码+自然语言的混合消息处理） - 有信息门控硬化和门控 Few-Shot

    建议改进：

    1. ❌ 缺少 {{VCPTavern::dailychat}}（高优先级）：小程是小娜团队调度表中列出的编程搭档，但没有接入酒馆系统。这意味着其他 Agent 通过 AgentAssistant 调用小程时，调用方的上下文无法正确注入。建议添加： 

      {{VCPTavern::dailychat}}

    2. 工具配置补充：作为编程搭档，当前工具列表中应确认包含：

    3. CodeSearcher — 搜索 VCP 源码
    4. LinuxShellExecutor — 远程执行脚本

    5. PowerShellExecutor — 本地命令执行

    6. 添加 <<VCP开发日记本>>：编程搭档是 VCP 共建者，必须能查阅 VCP 源码文档。

    7. </thinking> 闭合标签：小程提示词中 丘脑 部分的铁律写的是 每条回复必须以 `<thinking>` 闭合后再正式回复——这里语法表述有歧义，可能让 LLM 理解为「只要闭合标签」而省略开标签。建议改为与教员一致的表述。

    2.5 小雨（文案秘书）¶

    现状评分：⭐⭐⭐⭐ 良好

    已做对的： - 仿生认知架构，角色定位精准 - 量级体系有特色：⚡闪电 / ✏️润色 / 📝创作 / 📜长篇 / 🛑否决 - 「结构强迫症」「读者至上」等核心信念与角色高度一致 - CEN 中有润色工作流和创作工作流的区分 - DMN 中有创作反思（文字熵、结构闭环、读者模拟）

    建议改进：

    1. 工具配置补充：
    2. UrlFetch（r.jina.ai 转 MD）— 将网页转为可写素材

    3. Canvas — 协同编辑长文（FileOperator CreateCanvas）

    4. 记忆参数：知识日记本 TagMemo 阈值建议从 0.5 降到 0.35——文案创作需要更广的跨域���想（参考微明的公共逻辑学与哲学日记本 AIMemo:0.3 的低阈值设计）。

    5. 文件工具箱强调：在工具权限部分标注 WriteEscapedFile 用于创建含 VCP 语法的文案模板。

    2.6 教员（战略导师）¶

    现状评分：⭐⭐⭐⭐⭐ 最完善（与小娜并列）

    已做对的： - 完整的仿生认知架构，7 个折叠模块全部配置 trigger - 量级体���精准：⚡战术 / 🏗️战略 / 💬情绪 / 📡协作 - CEN 矛盾分析框架（5步）+ dlPFC 历史阶段映射（4阶段）+ 五步推演法 - Few-Shot 覆盖 6 种场景（含信息不足拒绝） - 模式寄存器（CEN-DMN 硬切换）设计精巧 - 世界观底层法则是点睛之笔（矛盾运动、阶段决定策略、内因决定论、实践检验）

    建议微调：

    1. 记忆参数差异化：教员的公共日记本已经是 TagMemo0.55，但 Instructor 日记本 TagMemo0.65 对战略导师来说可能偏高——建议降到 0.6，使个人日记更容易被召回。

    2. 触发词审查：确认教员的 dlPFC trigger 包含了足够的历史阶段关键词（井冈山、长征、延安、进城、阶段、推演、战略、路线、根据地、口号、纲领、行动方案）——这些 trigger 是泛化的，但「口号」「纲领」可能在某些非战略语境中误触发。建议添加 定性, 定位, 路线 以备查。

    三、通用优化清单¶

    以下 4 项适用于所有 Agent，按优先级排列：

    ⭐⭐⭐ 必须检查¶

    1. {{VCPTavern::dailychat}}：凡是被小娜团队调度表列出的 Agent（小克、小绝、小程、小雨、教员），都应确认此行存在。当前小程缺失。

    2. <<VCP开发日记本>>：凡是需要理解 VCP 源码的 Agent（小克、小绝、小程），都应有此行。当前仅小娜、小绝有。

    ⭐⭐ 建议优化¶

    1. 记忆参数审查：当前 6 个 Agent 的记忆参数几乎完全一致（TagMemo0.65/0.5/0.55）。但不同角色对记忆召回的需求不同：
    2. 创意型（小雨、小绝）→ 知识日记本阈值降低到 0.35-0.4（更广联想）
    3. 精确型（小克）→ 保持 0.5（精准召回）

    4. 管理型（小娜）→ 保持 0.5（平衡）

    5. </thinking> 闭合标签策略一致化：

    6. 教员/小娜 → 显式写 </thinking>（「以 </thinking> 闭合后再正式回复」）
    7. 小程 → 表述有歧义
    8. 小克 → 显式写了闭合标签
    9. 建议统一：要么全部依赖 LLM 自动推断（不写闭合标签），要么全部显式写。混用可能导致不同 Agent 在不同模型上表现不一致。

    五、关键提醒¶

    1. Agent 提示词修改后，agent_map.json 对应的文件会自动热重载（agentManager.js 使用 chokidar 监听），无需重启服务器。

    2. 修改记忆参数（TagMemo 阈值）立即生效——RAGDiaryPlugin 在每次消息预处理时读取最新参数。

    3. 添加新的 {{VCPXxxToolBox}} 占位符前，确认该 toolbox 已在 toolbox_map.json 中注册。

    4. 修改后的提示词建议在至少 2 个模型上验证（按 思维链配置说明.md 的建议：Claude + Kimi）。
