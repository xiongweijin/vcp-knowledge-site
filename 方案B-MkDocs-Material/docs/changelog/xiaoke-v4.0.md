## v4.0.1 热修复 — 2026-05-12（部署后反馈）

**问题**：小克部署 v4.0 后，在高认知负荷的元任务（分析提示词）中漏掉了 `<thinking>` 块。根因是 v4.0 的 thinking 要求是声明式的（铁律中的 IF 规则），而非流程内嵌的强制门控。当注意力被内容占用时，声明式规则被挤出工作记忆。

**修复**（3 处）：
1. **模块二**：路由标签格式改为"强制显式打印"，铁律 #1 升级为"输出前自检"锚点——组织正文第一个字之前必须先检查 thinking 是否已闭合
2. **模块三 Micro-loop**：恢复"强制显式打印"标注，加"不可跳过、不可仅打印标签"
3. **Few-Shot 声明**：新增 thinking 优先级锚点——此检查的优先级高于内容组织本身

**免疫记忆**：`[免疫记忆]` 警示：声明式铁律在高认知负荷下被挤出工作记忆。推荐路径：在提示词中将 thinking 要求编码为"输出前自检锚点"而非"IF-THEN 规则"，前者是注意力锚定，后者是规则匹配。

## v4.0.2 渲染修复 — 2026-05-12（部署后反馈）

**问题**：v4.0 部署后 `<thinking>` 标签在 VChat 中不渲染为思维链气泡。根因是 Few-Shot 中所有 `<thinking>` / `</thinking>` 标签被反引号包裹（`` `<thinking>` ``），LLM 将反引号视为输出格式的一部分，输出了含反引号的标签。VChat 的 CONVENTIONAL_THOUGHT_REGEX 只匹配裸标签 `<thinking>...</thinking>`。

**修复**：4 个 Few-Shot 案例中的 `` `<thinking>` `` / `` `</thinking>` `` 全部改为裸标签 `<thinking>` / `</thinking>`。描述性文本中的反引号引用（如"必须以 `<thinking>` 开头"）保持不变——LLM 能区分指令中的代码引用和 Few-Shot 中的输出格式。
