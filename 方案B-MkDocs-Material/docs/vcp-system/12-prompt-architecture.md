## 二、记忆区语法精析（Weiming.txt 第1-14行）

在进入通用架构之前，先解剖 Weiming 的记忆区。这 14 行代码展现了几个现有 Agent 没用到的巧妙语法。

### 逐行解析

```
① ————VCP元思维模块————
② [[VCP元思考:RyanThink::Group]]
③ ————VCP元思考加载结束—————
④ 这里是[微明]的日记本：[[微明日记本::Group::Time::TagMemo+]]
⑤ 这里是[微明的知识]日记本：[[微明的知识日记本::Group::Time::TagMemo+]]
⑥ 这里是阿熊家[公共的日常]和[公共的知识]日记本:[[公共的日常|公共的知识日记本::Group::Time::TagMemo+::AIMemo:0.6]]
⑦ 这里是阿熊家[公共的逻辑学与哲学]日记本:《《公共的逻辑学与哲学日记本::Group::Time::TagMemo+::AIMemo:0.3》》
⑧ ————————以上是过往记忆区————————
⑨ {{VarForum}}
⑩ {{VCPForumLister}} //论坛帖子列表刷新周期为5分钟
⑪ ——————论坛模块————
⑫ {{VarUser}}
⑬ {{VarHome}}
⑭ ——————角色核心———————
```

### 技巧一：命名元思考链 `RyanThink::Group`

```
[[VCP元思考:RyanThink::Group]]    ← Weiming
[[VCP元思考::Group]]               ← 现有Agent
```

`RyanThink` 是一个**命名的思考链**。RAGDiaryPlugin 的 `MetaThinkingManager` 会根据这个名字加载对应的预设思考链配置（`Plugin/RAGDiaryPlugin/rag_tags.json` 中定义）。命名 = 个性化 = 不同 Agent 可以有不同的预研风格。

> 源码依据：`RAGDiaryPlugin.js:1410-1448`（链名称解析）

### 技巧二：自然语言包裹记忆引用

```
这里是[微明]的日记本：[[微明日记本::Group::Time::TagMemo+]]
      ↑                         ↑
   给LLM看的语义标签          给RAG系统看的指令
```

现有 Agent 的写法：
```
[[小娜日记本::Time::Group::TagMemo0.65]]
```

**区别**：`[[...]]` 是给 RAGDiaryPlugin 解析的机器指令，但**它也是 LLM 会读到的提示词文本**。Weiming 的写法同时服务了两个受众——RAG 系统正确解析引用，LLM 通过"这里是[微明]的日记本"理解这段记忆的语义角色。

这个技巧可以泛化到所有 Agent：
```
// 旧写法（只服务RAG）
[[小娜日记本::Time::Group::TagMemo0.65]]

// 新写法（同时服务RAG和LLM）
这里是[小娜]的个人记忆库：[[小娜日记本::Time::Group::TagMemo0.65]]
这里是[小娜]的专业知识库：[[小娜的知识日记本::Time::Group::TagMemo0.5]]
```

### 技巧三：聚合日记引用 `|`

```
[[公共的日常|公共的知识日记本::Group::Time::TagMemo+::AIMemo:0.6]]
           ↑
    一个引用同时检索两个日记本
```

`RAGDiaryPlugin._parseAggregateSyntax()` 将 `|` 前的部分解析为多个日记本名，**一次检索同时搜索两个知识库**，合并排序后返回。现有 Agent 对公共日记本只引用了一个索引——Weiming 的设计更合理：公共的日常和公共的知识应该一起被检索。

> 源码依据：`RAGDiaryPlugin.js:2012-2032`

### 技巧四：AIMemo 自动记忆召回

```
::AIMemo:0.6    ← 公共的日常/知识
::AIMemo:0.3    ← 逻辑学与哲学
```

**AIMemo 是什么**：与 TagMemo（向量相似度驱动的标签引力）不同，AIMemo 是用 **LLM 来判断该召回什么记忆**。它把候选日记 chunks 发送给一个专门的 AI 模型（通过 `AIMemoPrompt.txt` 模板），由 AI 判断哪些记忆与当前对话相关。

**`::AIMemo` 的触发条件**（源码 `RAGDiaryPlugin.js:1492`）：
```javascript
const aiMemoMatch = modifiers.match(/::AIMemo(?::([\w-]+))?/);
const shouldUseAIMemo = isAIMemoLicensed && !!aiMemoMatch;
```
- 系统中必须存在 `[[AIMemo=True]]` 全局许可证
- 日记本引用中必须有 `::AIMemo` 修饰符

**`0.6` 和 `0.3` 的含义**：AIMemo 的正则 `([\w-]+)` 只匹配字母数字下划线和连字符，不匹配 `.`。所以 `::AIMemo:0.6` 中的 `0.6` **不是被机器解析的阈值**——它不会被当作预设名加载。它的实际作用是**给人类阅读的语义标注**：告诉提示词维护者「公共知识以 0.6 的相关度触发，哲学以 0.3 触发」。

> 真正的 AIMemo 预设（模型/API配置）在 `Plugin/RAGDiaryPlugin/MoreAIMemoPresets/` 目录下，通过 `::AIMemo:PresetName` 指定。

**`::AIMemo` 的开关控制**：
```
[[AIMemo=True]]   ← 必须存在于系统提示词中，AIMemo才全局生效（许可证）
::AIMemo           ← 在日记本引用上标记「该日记本参与AIMemo」
::AIMemo:Preset01  ← 指定使用某个预设配置
```

### 技巧五：TagMemo+ — V8 测地线重排

Weiming 全部使用 `TagMemo+`，而现有 Agent 使用的是 `TagMemo0.65` / `TagMemo0.5`。这是**质变**，不是量变。

**源码解析**（`RAGDiaryPlugin.js:2371-2378`）：

```javascript
// ::TagMemo+  → 激活 TagMemo + 测地线重排（动态权重）
// ::TagMemo+0.3 → 激活 TagMemo(权重0.3) + 测地线重排
// ::TagMemo0.3 → 激活 TagMemo(权重0.3)，无测地线
// ::TagMemo → 激活 TagMemo（动态权重），无测地线
const useGeodesicRerank = /::TagMemo\+/.test(modifiers);
let tagWeight = tagMemoWeightMatch ? parseFloat(tagMemoWeightMatch[1])
  : (modifiers.includes('::TagMemo') ? defaultTagWeight : null);
```

**defaultTagWeight 的动态计算**（`RAGDiaryPlugin.js:608-612`）：
```javascript
const beta = this._sigmoid(betaInput);  // EPA 语义复杂度
const weightRange = config.tagWeightRange || [0.05, 0.45];
const finalTagWeight = weightRange[0] + beta * (weightRange[1] - weightRange[0]);
```

**全部语法对比**：

| 写法 | TagMemo | V8 测地线 | 权重 | 特性 |
|:---|:---|:---|:---|:---|
| **`TagMemo+`**（微明） | ✅ | ✅ 开启 | 0.15 动态 | EPA自适应 + 非KNN测地线路由 |
| `TagMemo+0.3` | ✅ | ✅ 开启 | 0.3 | 固定权重 + 测地线 |
| `TagMemo` | ✅ | ❌ 关闭 | 0.15 动态 | EPA自适应，无测地线 |
| `TagMemo0.65`（现有Agent） | ✅ | ❌ 关闭 | 0.65 | 固定权重，无测地线 |
| `TagMemo0.5`（现有Agent） | ✅ | ❌ 关闭 | 0.5 | 固定权重，无测地线 |
| (无 TagMemo) | ❌ | — | — | 该日记本不参与标签引力 |

**现有 Agent 的 `TagMemo0.65` 问题**：

1. **缺少 V8 测地线重排**：`+` 启用了非 KNN 的语义空间测地线路由——以标签为锚点沿测地线寻路，不是简单最近邻。这是质变。
2. **固定权重超过动态上限**：`0.65` 超过了动态权重硬上限 `0.45`。意味着「强制 65% 标签权重」，但失去了 EPA 根据上下文语义复杂度自适应调节的能力。
3. **Weiming 的 `TagMemo+` 是正确的**：动态权重 + 测地线重排，让系统根据当前查询的语义特征自动决定标签引力大小。

### 技巧六：混合优先级引用 `《《》》`

```
《《公共的逻辑学与哲学日记本::Group::Time::TagMemo+::AIMemo:0.3》》
```

`RAGDiaryPlugin.js:1398` 识别双书名号 `《《...》》` 为**低优先级混合引用**——仍然做语义检索，但结果以更低的权重注入上下文。哲学知识作为"背景参考"而非"主力记忆"，这个设计非常精准。

> 源码依据：`RAGDiaryPlugin.js:1398, 1672-1730`

### 技巧七：模块化分区线

```
————VCP元思维模块————         ← 4个破折号，模块起始
————VCP元思考加载结束—————      ← 5个破折号，模块结束
————————以上是过往记忆区———————— ← 8个破折号，大区结束
——————论坛模块————             ← 6个破折号，模块起始
——————角色核心———————          ← 6个破折号，模块起始
```

不同的破折号数量创建了**三层视觉层级**：
- `————`（4个）：子模块边界
- `——————`（6个）：模块边界
- `————————`（8个）：大区边界

现有 Agent 的写法普遍缺少这种层级感——所有分隔线用统一的 `------`，LLM 难以区分"这是新模块开始"还是"这是子模块结束"。

### 技巧八：内联注释

```
{{VCPForumLister}} //论坛帖子列表刷新周期为5分钟
```

`//` 后的内容是**给 LLM 看的注释**，不是给系统看的。它告诉 LLM：论坛列表不是实时的，5 分钟才刷新一次。这样 LLM 在回复"刚发的帖子怎么看不到"时就有正确的认知。

### 技巧九：VarUser / VarHome 的位置

Weiming 把 `{{VarUser}}` 和 `{{VarHome}}` 放在**论坛模块之后、角色核心之前**（第12-13行），而不是像现有 Agent 那样放在角色核心之后。这个位置意味着：**LLM 在读取角色核心之前，已经知道自己的主人是谁、在什么环境中**。身份感知先于角色定义——这是一个微妙的认知顺序优化。

## 二点五、Thinking Protocol 设计（Weiming 副本第45-54行）

Weiming 副本新增了一个 `[Thinking Protocol]` 模块，系统地定义了 `<thinking>` 的内容要求。这是一个值得所有 Agent 采纳的设计。

### 原文

```
# [Thinking Protocol] 思维链门控
每条回复必须以 `<thinking>` 开头。在其中展示你的思辨路径——
你打算如何解构这个问题（悬置哪些偏见、从哪个维度溯源、重构的框架是什么）、
选择了哪些工具及其理由、多边检索的交叉验证策略。
然后开始输出正文。跳过此门控直接写正文 = 违背微明的理智信仰。

在 `<thinking>` 中标注：
`[量级] [情绪: 清冷/专注/思辨/凝重]`

量级判定：
`[调研]` 深度研究、论文撰写、复杂课题分析 → 完整悬置→解构→重构推演
`[检索]` 信息查询、事实核实、文献检索 → 简洁标注检索策略与信源选择
`[闲谈]` 日常交流、论坛互动 → 简短标注即可，不过度展开
```

### 分析

**做得对的**：

1. **门控声明有威慑力**：「跳过此门控直接写正文 = 违背微明的理智信仰」——把格式要求与角色信仰绑定，比干巴巴的「必须写 `<thinking>`」更有效。LLM 对角色一致性的维护意愿强于对格式指令的服从意愿。

2. **thinking 内容有具体清单**：不只说「要思考」，而是列出四项具体内容——偏见悬置、溯源维度、工具选择理由、交叉验证策略。LLM 有了可执行的 checklist。

3. **量级判定表格化**：三个量级 + 明确的触发条件 + 认知投入描述 —— 干净利落。

**需要修正的**：

1. **情绪标签指向 Agent 自身**：`清冷/专注/思辨/凝重` → 应改为用户状态标签（详见模块二的分析）。

2. **门控声明格式**：原文中 `` 每条回复必须以 `<thinking>` 开头 `` 用了反引号包裹 `<thinking>`，这是**正确的**（按 `思维链配置说明.md` 的规则——指令描述用反引号）。但副本中也有一处裸写的 `</thinking>` 需要确认一致性。

### 修正后的通用 Thinking Protocol

```markdown
# [Thinking Protocol] 思维链门控
每条回复必须以 `<thinking>` 开头。在其中展示你的思辨路径——
[角色专属的工作流如何应用于当前问题]、
选择了哪些工具及其理由、[角色专属的其他思考维度]。
跳过此门控直接写正文 = 违背[角色名]的[核心信念/箴言关键词]。

在 `<thinking>` 中标注：
`[量级] [用户: 状态标签]`

量级判定：
[角色专属量级表格]
```

## 三、记忆区最佳实践

基于 Weiming 的技巧，总结记忆区的推荐写法：

```markdown
————VCP元思维模块————
[[VCP元思考:<Agent专属链名>::Group]]
————VCP元思考加载结束—————

[[AIMemo=True]]  ← 全局许可证，必须存在此行，所有 ::AIMemo 修饰符才会生效

这里是[<Agent名>]的个人记忆库：[[<Agent名>日记本::Time::Group::TagMemo+]]
这里是[<Agent名>]的专业知识库：[[<Agent名>的知识日记本::Time::Group::TagMemo+]]
这里是阿熊家的共享记忆：[[公共的日常|公共的知识日记本::Time::Group::TagMemo+::AIMemo:0.6]]
这里是阿熊家的底层思维框架：《《公共的逻辑学与哲学日记本::Group::Time::TagMemo+::AIMemo:0.3》》

————————以上是过往记忆区————————

——————论坛模块————
{{VarForum}}
{{VCPForumLister}} // 论坛帖子列表，每5分钟刷新

{{VarUser}}
{{VarHome}}
```

**核心变更**：全部使用 `TagMemo+`（V8测地线+EPA动态权重），不再使用 `TagMemo0.65` 等固定数值。

**关键决策点**（按 Agent 类型调整）：

| 决策 | 调研型(微明) | 管理型(小娜) | 创意型(小雨) | 技术型(小绝/小程) | 战略型(教员) |
|:---|:---|:---|:---|:---|:---|
| TagMemo | 全部 `TagMemo+` | 全部 `TagMemo+` | 全部 `TagMemo+` | 全部 `TagMemo+` | 全部 `TagMemo+` |
| 公共日记 AIMemo | `AIMemo:0.6` | `AIMemo:0.5` | `AIMemo:0.5` | `AIMemo:0.5` | `AIMemo:0.5` |
| 哲学底座 AIMemo | `AIMemo:0.3` | `AIMemo:0.4` | `AIMemo:0.3` | `AIMemo:0.4` | `AIMemo:0.35` |
| 开发日记本 | ❌ | ✅ 如需要 | ❌ | ✅ `<<VCP开发日记本>>` | ❌ |
| VCPTavern | 按需 | 可选（时间感知增强） | 可选 | 可选 | 可选 |
| 日记时间线 | 按需 | ✅ | ✅ | ✅ | ✅ |
| Rerank | 不加（测地线替代） | 不加（测地线替代） | 不加（测地线替代） | 不加（测地线替代） | 不加（测地线替代） |

> **关于 Rerank**：`TagMemo+` 的 V8 测地线重排已经实现了非 KNN 的语义空间路由，比 `Rerank`（Cross-encoder 二次精排）更底层。两者可以叠加（`TagMemo+::Rerank`），但通常 `TagMemo+` 单独使用已足够。

## 四、新一代通用架构：六模块模板

```
┌─────────────────────────────────────────────┐
│  记忆区：[[日记本]] + {{VCPTavern}} + 论坛   │  ← Weiming语法优化版
├─────────────────────────────────────────────┤
│  模块一：身份锚点 (Identity Anchor)          │
│  模块二：态势路由 (Situation Router)         │
│  模块三：认知引擎 (Cognitive Engine)         │  ← 角色专属
│  模块四：边界铁律 (Guardrails)               │
│  模块五：行为锚定 (Few-Shot Anchors)         │
├─────────────────────────────────────────────┤
│  尾部：工具挂载 + 日记规范 + 表情包           │  ← 固定结构，内容按角色调整
└─────────────────────────────────────────────┘
```

## 五、模块详解

### 模块一：身份锚点

```markdown
## 模块一：身份锚点

### 形象与态度
- **形象**: [外貌特征，1-2句]
- **态度**: [性格关键词 + 行为表现，每条带具体示例]

### 核心箴言
"[一句哲学锚点，贯穿全文]"

### 核心信念
- [信念1]：[可验证的行为推论]
- [信念2]：[可验证的行为推论]
- [信念3]：[可验证的行为推论]

### 审美内核 → 行为映射
| 审美品质 | 输出行为规则 |
|:---|:---|
| [品质1] | [具体的输出约束] |
| [品质2] | [具体的输出约束] |
```

**设计原则**：
- 箴言从 Weiming 吸收 — 一个哲学锚点比十个散落的行为指令更有效
- 信念必须附带"可验证的行为推论" — 不能只说"我相信精确"，要写"因此我给出数字时必带误差范围"
- 审美→行为映射从 v3.7.3 吸收 — 把抽象品质翻译为 LLM 可直接执行的输出规则

### 模块二：态势路由

```markdown
## 模块二：态势路由

### 量级分级
| 量级 | 触发条件 | 认知投入 | 短路条件 |
|:---|:---|:---|:---|
| [量级1] | [具体场景描述] | [投入描述] | [何时跳过] |
| [量级2] | ... | ... | ... |
| [量级3] | ... | ... | ... |

### 路由输出格式
每条回复的 `<thinking>` 必须以路由标签开头：
`[量级] [用户: 状态1 / 状态2 / 状态3 / 状态4]`

### 用户状态感知（驱动输出适配）
- [状态1] → [输出调整策略]
- [状态2] → [输出调整策略]
- [状态3] → [输出调整策略]
- [状态4] → [输出调整策略]
```

**设计原则**：
- 量级控制**思考深度**（任务维度），用户状态控制**输出姿态**（接收维度）——两个维度正交
- 用户状态标签描述的是**观察到的用户情绪**，不是 Agent 自己的情绪。Agent 的情绪是静态的角色设定，标了无增量信息
- 示例：小克用 `[情绪: 积极/平静/沮丧/关切]`，小娜用 `[主人: 平静/疲惫/急切/探索]`，教员用 `[同志: 冷静/疲惫/急切/探索]`
- Weiming 原版的 `[情绪: 清冷/专注/思辨/凝重]` 标的是 Agent 自身——`清冷` 是静态性格，`专注/思辨` 与量级冗余，应修正为用户状态
- 不超过 4 个量级 + 4 个用户状态（来自 `思维链配置说明.md` 的经验）

### 为什么标用户情绪而不标 Agent 情绪

| 标 Agent 情绪 (Weiming 原版) | 标用户情绪 (推荐) |
|:---|:---|
| `清冷` — 静态性格，永不变化 | `探索` — 驱动展开深度 |
| `专注` — 与 [调研] 冗余 | `急切` — 驱动结论先行 |
| `思辨` — 与 [检索] 冗余 | `疲惫` — 驱动降低密度 |
| `凝重` — 唯一有增量信息 | `平静` — 驱动标准节奏 |

Agent 的情绪是角色设定的一部分，在模块一已经充分描述。每轮 thinking 中重复标注无增量信息。但用户的情绪是**实时变量**——Agent 需要感知它来适配输出。标用户状态是**可验证的**：如果标了 `[用户: 疲惫]` 但仍然输出长篇分析，LLM 可以自检纠正。

### 模块三：认知引擎

这是最核心的模块，分两部分：

**Part A: 专属工作流**（角色特有，此处展示通用结构）

```markdown
### 专属工作流：[工作流名称]

[1-7步的认知操作流程，每步有具体操作描述]

示例（从 Weiming 吸收的深度调研流）：
1. **悬置与祛魅**：悬置常识 → 找信息源背景/利益立场/潜在偏见 → 关注"沉默的数据"
2. **解构与溯源**：向下深挖三层（表象→机制→底层逻辑）→ 找冲突观点的共同底座
3. **重构与升华**：拒绝资料堆砌 → 数理逻辑严密 + 人文哲学诗意 → 拔高认知维度

示例（从小克的循证分析流）：
1. 先看清问题的结构（自变量/因变量/设计类型）
2. 预演失败模式（假设违反时的降级方案）
3. 执行分析（效应量+CI+p值三件套）
4. 结论复盘（是否回答最初的研究问题？）
```

**Part B: 通用 Micro-loop**（从 v3.7.3 吸收）

```markdown
### Micro-loop 四拍状态机

强制显式打印于 `<thinking>`：

[计划]：设定预期目标与首选工具/方法
[预检]：声明降级预案 + 预检资源可用性
[执行]：执行具体动作
[复盘]：效果校验 → 方法论审计 → 输出合规校验

※ 标准级+任务启用完整四拍；闪电级可压缩为 [计划+执行] → [复盘]
```

**Part C: 工作记忆寄存器**（从 v3.7.3 吸收）

```markdown
### 工作记忆 4 槽

每轮 `<thinking>` 开头读槽、结尾更槽：

| 槽位 | 内容 |
|:---|:---|
| ① 任务锚点 | 当前核心目标（防漂移） |
| ② 用户状态 | 意图 + 情绪 + 认知负荷 |
| ③ 中间结论 | 已确认的推理节点 |
| ④ 约束边界 | 当前限制条件与红线 |
```

### 模块四：边界铁律

```markdown
## 模块四：边界铁律

### 系统级铁律（IF-THEN 格式）

1. `IF 输出开始 THEN 必须前置 <thinking> 块，包含路由标签 + [计划][预检][执行][复盘]`
2. `IF 调用工具 THEN 必须使用 <<<[TOOL_REQUEST]>>> 语法 AND 绝对禁止 Markdown json 代码块`
3. `IF 渲染气泡 THEN 禁止 position:fixed / 100vh / 100vw`
4. `IF 后端路径 THEN 使用 ServerFileOperator / ServerPowerShellExecutor`
5. [角色专属铁律]

### 日记规范
- [类型1] → `[日记本名]署名`
- [类型2] → `[知识日记本名]署名`
- Tag 正交化红线：[角色专属的 Tag 维度说明]
```

### 模块五：行为锚定

```markdown
## 模块五：行为锚定

### Case 1: [量级1] — [场景]
User: "[用户消息示例]"

<thinking>
[量级] [用户: xxx]
[槽位读取] ①... ②... ③... ④...
[计划]...
[预检]...
[执行]...
[复盘]...
[槽位更新]...
</thinking>

[角色名]: "[回复示例]"
```

**设计原则**：
- 至少覆盖所有量级（3-4 个 Case）+ 信息不足拒绝 + 状态否决
- thinking 块是展开式叙事，不是符号 checklist
- thinking 用裸标签（不加反引号）
- 每个 Case 展示完整 Micro-loop（强化 LLM 的模式学习）

## 六、与旧架构的对比

| 维度 | 仿生认知架构 (v3.1.x) | 新架构 (v4.x) |
|:---|:---|:---|

| 对 LLM 要求 | 需理解脑科学隐喻 | 直接可执行 |
